# 제품 기획

> 초기 작성: 2026-10-02. 사용자 요청으로 확정한 방향과 현재 저장소에서 확인한 내용을 기록한다. 미결정 사항은 `미정`으로 남긴다.

제품 목적, 범위, 사용자 흐름과 정책을 다룬다. 개별 작업은 [docs/README.md](README.md)의 작업 목록에서 찾는다.

## 목적과 사용자

접근성(a11y)과 관련된 도구 및 데이터 분석 페이지를 하나씩 추가한다. 메인 페이지에서 각 도구와 분석 페이지로 이동할 수 있도록 구성한다. 이는 사용자가 정한 제품 방향이며, 현재 구현은 조사 문서와 오프라인 분석 코드 단계다.

첫 분석 주제는 디지털포용법 시행 전후 변화다. 공개 자료로 분석 가능한 범위를 먼저 진행하고, 사용자가 API 키를 발급한 후 추가 분석을 이어간다.

- 주요 이용자와 우선 해결할 이용자의 문제: 미정.
- 기존 조사 문서에서 제안한 도구 중 실제 제공할 항목과 순서: 미정.
- 코드·문서 근거: [README.md](../README.md), [analyses/digital-inclusion/plan.json](../analyses/digital-inclusion/plan.json).

## 이번 범위

- 제공할 것: 접근성 관련 조사 문서, 디지털포용법 초기 분석 결과·입력 데이터·계산 코드, 후속 분석에 필요한 API 안내.
- 공개 사이트와 저장소 첫 화면([README.md](../README.md))에서 연결하지 않을 것: 도구 아이디어 문서([docs/ideas.md](ideas.md))는 아이디어를 얻기 위한 개인 참고 자료다(사용자 요청, 2026-10-06).
- 인증 수집 분석: 조달청·행안부 실제 자료로 현재 기능과 동일 기간 조달 순증을 확인했다. KOSIS로 2016년 이후 장기 기준선과 기존 보고서 대조도 완료했다. 결과는 W-002·W-003에 있으며 다음 이력 확보는 [docs/work/W-004-main-history-data.md](work/W-004-main-history-data.md)에서 관리한다.
- 메인 페이지와 개별 도구·분석 페이지: GitHub Pages로 배포하고, 메인 허브에서 각 HTML 문서와 웹 서비스로 들어가며, 한 저장소에 여러 서비스를 함께 두는 구조는 사용자 요청으로 확정했다(2026-10-06). 첫 페이지로 허브와 디지털포용법 분석 보고서를 만들어 2026-10-06에 `https://gonasooc.github.io/a11y/`로 공개했다. 근거: [docs/work/W-006-main-pages-site.md](work/W-006-main-pages-site.md).
- 성공 기준: 현재 분석은 출처와 계산을 확인할 수 있고, 결과의 해석 범위와 필요한 후속 자료가 명시돼 있어야 한다. 웹 서비스의 출시 기준과 이용 지표는 미정.

## 핵심 기능과 사용자 흐름

| 기능 | 현재 상태 | 목표 흐름 |
|---|---|---|
| 도구·분석 진입점 | `https://gonasooc.github.io/a11y/`의 허브(`site/index.html`)가 각 페이지로 링크한다 | 메인 페이지에서 항목을 선택한다 |
| 디지털포용법 분석 | 초기 결과 보고서, 재현 가능한 출력 데이터, 차트로 정리한 웹 보고서가 있다 | 분석 결과 → 출처·기간·한계 → 추가 자료 확인 |
| 접근성 도구 | 기존 문서에 아이디어가 있다 | 구체적인 도구와 이용 흐름은 미정 |
| 후속 데이터 분석 | 조달청·행안부·KOSIS 인증 수집과 기술통계가 있다 | 자료 확보 → 품질·범위·출처 간 차이 점검 → 결과·해석 한계 확인 |

현재 분석 보고서는 [docs/digital-inclusion-analysis.md](digital-inclusion-analysis.md), API 안내는 [docs/10-digital-inclusion-api-guide.md](10-digital-inclusion-api-guide.md)에 있다.

## 제품 정책과 제약

- 확정된 작업 방식: 한국어 문서를 공통 작업 맥락으로 사용한다. 제품·구조·기술 규칙과 개별 작업의 상태를 역할별 문서에서 관리한다. 근거: [docs/work/W-001-main-docs-starter.md](work/W-001-main-docs-starter.md).
- 현재 분석의 판단 기준: 관찰한 변화와 정책의 인과효과를 구분한다. 자료로 효과를 식별할 수 없으면 판단 불가로 표시한다. 근거: [analyses/digital-inclusion/plan.json](../analyses/digital-inclusion/plan.json).
- 데이터 신뢰 범위: 이번에 원문을 확인한 통계와 기존 문서 집계의 재계산을 구분한다. 수집 실패·기간 불일치·갱신 여부 등 해석에 영향을 주는 한계를 결과에 연결한다.
- API 키 발급 후 추가 분석한다는 순서는 확정돼 있다. 키만으로 과거 데이터나 미공표 통계가 생기지는 않으므로, 실제 응답을 확인한 뒤 분석 범위를 결정한다.
- 도구별 이용 정책, 사용자 데이터 보관, 인증·계정 필요 여부, 라이선스와 배포 정책: 미정.

## 아직 결정할 사항

- 첫 웹 공개의 주요 이용자, 제공할 도구와 분석 페이지 범위.
- 분석 결과의 갱신 주기, 과거 결과의 공개 방식, 수동 검토 절차.
- 도구 페이지에 필요한 추가 기술(프레임워크·서버)과 사용자 데이터 처리 방식. 기술 결정을 하면 [docs/specs.md](specs.md)에 반영한다.
- [docs/design.md](design.md)의 현재 구현 기준을 합의된 디자인·접근성 기준으로 확정할지.

현재 상태와 다음 행동은 각 작업 문서에서 관리한다.
