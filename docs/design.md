# 디자인 기준

> 초기 작성: 2026-10-06 · 2026-10-12 보고서 페이지 구성 기준 추가 · 같은 날 사용자 요청으로 글꼴을 Pretendard 하나로 줄이고 장식을 걷어냈으며, 밝은 화면만 남기고 머리글·바닥글을 정리했다. [site/](../site/) 구현에서 정한 기준이며, 글꼴·장식 제거·밝은 화면·머리글 구성·바닥글의 구어체 금지는 사용자가 정했고 나머지는 검토 전이다. 근거와 검증은 [docs/work/W-006-main-pages-site.md](work/W-006-main-pages-site.md)에 있다.

UI의 시각 기준과 상호작용·반응형·접근성 기준을 다룬다. 폴더 구조와 도구 설정은 [docs/architecture.md](architecture.md)와 [docs/specs.md](specs.md)에 있다.

## 방향

- 신뢰가 중요한 페이지이므로 모던하고 담백하게 만든다(사용자 요청, 2026-10-06). 도장·기울임·등장 애니메이션 같은 장식은 쓰지 않는다.
- 강조는 굵기와 크기, 중립색으로 한다. 판정처럼 중요한 상태는 아이콘·글자·3단계 표시를 함께 써서 색에 기대지 않는다.

## 토큰과 글꼴

- 글꼴은 Pretendard 하나만 쓴다(사용자 요청). jsDelivr의 가변 다이나믹 서브셋 CSS를 첫 화면을 막지 않게 늦게 적용하고, 도착 전에는 시스템 한글 글꼴로 보인다. 코드와 명령도 Pretendard로 쓰고 숫자는 고정폭 숫자(`tabular-nums`)로 맞춘다.
- 색 토큰은 [site/assets/css/tokens.css](../site/assets/css/tokens.css) 한 곳에서 관리한다. 화면은 밝은 버전 하나만 둔다(사용자 요청, 2026-10-06). 회색 바탕(`#f6f7f9`)에 흰 카드를 쓰고, 운영체제가 어두운 모드여도 `color-scheme: light`로 밝게 보인다. 테마 선택은 두지 않는다.
- 글자 색(`--ink`, `--ink-2`, `--muted`, `--link`)은 바탕·카드·옅은 면 모두에서 4.5:1 이상이다.
- 제목은 굵게(700) 쓰고 자간을 조금 좁힌다. 본문은 17px, 줄 간격 1.75, 한 줄 70자 안팎. 한국어 줄바꿈은 `word-break: keep-all`. 큰 수치는 비례 숫자, 표와 축 눈금은 고정폭 숫자를 쓴다.
- 제목은 `text-wrap: balance`로 줄 길이를 맞춘다(관찰된 구현). 그래서 좁은 화면에서 가운뎃점(·)으로 이은 말이 가운뎃점 앞에서 끊길 수 있다. 가운뎃점은 앞말과 묶어 줄 첫머리에 오지 않게 하고, 한두 낱말만 남는 마지막 줄은 줄바꿈 없는 공백으로 묶는다(구현 기준, 2026-10-14, [docs/work/W-010-main-media-access-report.md](work/W-010-main-media-access-report.md)).

## 머리글·바닥글·허브 구성

- 머리글에는 사이트 이름과 페이지 이동 링크만 둔다. 저장소 메뉴와 테마 선택은 두지 않는다(사용자 요청, 2026-10-06). 현재 보고서 머리글에는 ‘전체 목록’만 있다. 근거 문서는 절마다 ‘이 절의 근거’ 줄과 바닥글에 둔다(사용자 결정, 2026-10-12).
- 바닥글 문구는 구어체로 쓰지 않는다(사용자 요청, 2026-10-06). 현재 구현은 명사형 종결이다(예: ‘법률 자문에 해당하지 않음’, ‘소스 코드: gonasooc/a11y’).
- 허브에는 페이지 목록만 둔다. 각 페이지가 자료 출처와 분석 재현 링크를 페이지 안에 두므로, 허브에 ‘원문과 조사 문서’ 같은 모음 섹션을 두지 않는다(사용자 요청, 2026-10-06). 사이트 제작 방식을 소개하던 섹션도 사용자 요청으로 뺐다.

## 보고서 페이지 구성

아래는 디지털포용법 보고서에 사용자가 정한 기준이다(2026-10-12, [docs/work/W-007-main-lay-reader-report.md](work/W-007-main-lay-reader-report.md)). 다른 보고서에도 같은 독자를 둔다면 따른다.

- 첫 화면은 제목(독자의 질문), 부제, 한 문장 설명, ‘한눈에 보기’ 카드 세 장이다. 카드마다 굵은 숫자 하나 이상과 조사 이름을 둔다. 판정 카드나 숫자만 모은 카드는 두지 않는다.
- 본문은 독자가 품을 질문을 절 제목으로 쓴다. 분석 과정(자료 범위, 세부 분해, 출처 대조, 재현)은 맨 아래 ‘분석 노트’에 제목만 보이게 접어 둔다.
- 절마다 끝에 ‘이 절의 근거’ 줄을 둔다. 숫자마다 원출처 링크나 조사 이름을 단다. 조사 대상이 다른 숫자를 나란히 쓸 때는 조사 이름을 반드시 붙인다.
- 상대지수는 ‘일반국민을 100으로 볼 때’로 쓰고 100 기준선 막대로 보여 준다. ‘점’과 ‘%’를 붙이지 않고, 처음 나오는 곳에서 점수나 비율이 아님을 풀이한다.
- 장애유형별 장면은 공식 점검·통계로 확인한 사실만 쓴다. 실명 발언 인용과 지어낸 인물은 쓰지 않는다.
- 문체는 ‘~한다’체다. 용어는 처음 나올 때 풀어 쓰고, 한 문장에는 정보를 하나만 담고, 숫자에는 기준 연도와 단위를 붙인다.
- 본문 숫자는 모두 생성 스크립트로 대조한다. 대조하지 않는 숫자는 날짜·연도·기간, 나이 범위, 조사 설계의 유형 수, 지수 기준값 100, 절·그림·조항·표 번호, 인용 문구 안 숫자, 식별번호뿐이다.

## 차트

- 차트 색은 dataviz 기준 팔레트의 고정 순서를 쓴다. 범주형은 5개까지(점 그림처럼 모든 쌍이 맞닿는 형태는 3개까지)이고, 순서를 바꾸거나 색을 만들어 쓰지 않는다. 흰 카드 면(`#ffffff`)에서 검사해 통과했다.
- 3~5번 계열은 카드 면 대비가 3:1 미만이다. 그 계열을 쓰는 차트에는 직접 라벨이나 표 보기를 반드시 둔다.
- 두 시점 비교는 같은 파랑의 두 단계(`--before`, `--after`), 비교 밖의 값은 회색(`--deemph`), 감소·증가는 빨강·파랑(`--dec`, `--inc`)을 쓴다. 상태색(`--warning`)은 출처 불일치처럼 의미가 있을 때만 아이콘·글자와 함께 쓴다.
- 표식: 막대 두께 24px 이하·끝만 4px 둥글게, 선 2px, 점 지름 8px 이상과 2px 면색 테두리, 격자는 실선 머리카락 선. 글자는 계열 색이 아니라 글자 토큰으로 쓴다.
- 연도처럼 축 라벨이 많은 세로 막대는 칸이 좁으면 짧은 라벨(’17)을 쓴다. 값 단위의 이름에는 전체 연도를 쓴다(구현 기준, 2026-10-13, [docs/work/W-010-main-media-access-report.md](work/W-010-main-media-access-report.md)).
- 계열이 둘 이상이면 범례를 항상 두고, 4개 이하는 직접 라벨도 단다. 계열이 하나면 범례를 두지 않는다. 모든 점에 숫자를 쓰지 않는다. 칸이 좁아 라벨이 맞닿으면 라벨만 작게 쓴다.
- 기준과 비교하는 값은 가로 막대와 기준선(일반국민 100, 평균 등)으로 그린다. 값 글자가 기준선에 걸리면 선 오른쪽으로 비켜 쓴다. 조사 기간 밖의 사건(법 시행일)은 마지막 조사연도 뒤에 세로선과 짧은 설명으로 표시한다.

## 상호작용과 접근성

- 차트마다 같은 값을 담은 표를 ‘표로 보기’(`<details>`)에 둔다. 표는 생성 스크립트가 HTML에 정적으로 넣어 자바스크립트 없이도 읽힌다.
- 차트 하나에 탭 정지점은 하나다. 화살표·Home·End로 값 단위를 옮기고, 마우스를 올렸을 때와 같은 툴팁과 포커스 고리가 보인다. 값 단위는 `role="img"`와 전체 문장의 이름을 가진다. 차트는 그림 제목과 요약 문장을 `aria-labelledby`·`aria-describedby`로 가리킨다.
- 툴팁은 보조 수단이다. 툴팁에만 있는 값을 만들지 않는다.
- 320px 폭에서 본문이 가로로 넘치지 않아야 한다. 넓은 표는 이름이 있는 스크롤 영역 안에서만 넘친다. 머리글은 넓은 화면에서만 고정해 확대·좁은 화면에서 초점을 가리지 않게 한다.
- 움직임은 쓰지 않는다. 강제 색상 모드에서는 시스템 색으로 표식을 다시 칠한다.
- 공개 전 확인: axe-core(WCAG 2.2 AA·best-practice) 위반 0, 키보드만으로 모든 차트 값 읽기, 320px 화면 확인, 운영체제가 어두운 모드여도 밝게 보이는지 확인.

## 불일치·미정

- 실제 스크린리더별 낭독 확인은 아직 하지 않았다.
- 허브 카드의 미리보기 이미지, 인쇄 전용 배치, 도구 페이지의 입력 컴포넌트 기준은 미정이다.
