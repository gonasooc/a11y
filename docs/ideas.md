## 2. 공통 설계 전제와 적용 범위

아래는 기존 조사에서 도출한 **설계 제안**이다. 저장소의 모든 제품에 확정 적용된 정책으로 취급하지 않는다.

1. **모바일에서 실제 과업을 본다.** PC 확장만으로 끝내지 않고 Safari 확장, Android 앱, 공유하기, 모바일 웹 등 가능한 진입 경로를 확인한다. 화면낭독뿐 아니라 확대·대비·리플로우·키보드·음성·스위치와 이해 지원도 고려한다.
2. **범용 AI 설명과 구체적인 문제를 구분한다.** OS와 기존 서비스가 제공하는 기능 위에 한국어 상품 상세, 금융 과업, 실패 기록처럼 검증할 범위를 정한다. 장애정도 비율을 제품 수요로, 전용 보조기기 보유율을 내장 기능 이용률로 환산하지 않는다.
3. **사용자의 선택과 결과 확인을 지킨다.** 자동 추정·쉬운 글은 초안임을 표시하고 원문과 대조한다. 설명, 실행 요청, 실제 완료 상태를 구분하고 되돌릴 수 있게 한다. 금전·신청·취소 등 되돌리기 어려운 행동은 확인을 받는다.
4. **민감한 정보는 최소한으로 다룬다.** 기기 안 OCR·가림을 먼저 검토하고, 보낼 화면과 지원 요청은 사용자가 고른다. 저장·공유 범위, 접근 권한, 삭제·만료를 함께 설계한다. OS의 보조기술 사용 여부를 몰래 탐지하거나 광고·가격 차등에 이용하지 않는다.
5. **우회와 공급자 개선을 함께 본다.** 사용자 우회 도구를 기업의 법적 준수 대체 수단으로 판매한다는 제안은 하지 않는다. 반면 기관이 자기 서비스·콘텐츠·검수·운영을 고치는 데 비용을 내는 모델은 별도 검토 대상이다. 둘을 ‘모든 도구는 사용자 설치형이어야 한다’는 한 규칙으로 합치지 않는다.
6. **관문은 공급자와 해결한다.** 인증·보안 입력·결제의 보호조치를 우회하는 기능을 제안하지 않는다. 사용자 본인 계정과 정상 절차의 실패를 기록하고 접근 가능한 대안 구현·처리 권한을 공급자와 검토한다.
7. **측정 단위와 상태를 분리한다.** 자동 오류 탐지와 전문가 평가, 공급자 신고와 당사자 확인, 검증 모델과 설치 기기, 저장과 제출, 접수와 해결, 수정 통보와 재시험을 같은 값으로 표시하지 않는다. 자동 측정은 공식 점수의 대체나 단순 순위표가 아니다.
8. **당사자에게 검증 부담을 무급으로 넘기지 않는다.** 모집·동의·시험·결과 확인·보수 수령까지 접근 가능하게 준비한다. 참여 보수는 성공이나 결함 발견 여부에 연동하지 않는다. 이용자가 원한 도움과 장벽 때문에 불가피한 타인 의존을 구분한다.
9. **운영과 유지 조건을 먼저 확인한다.** 사이트 개편, 앱 버전, 규정·지원사업 변경으로 깨질 것을 전제로 확인일·버전·알림·수정 책임을 둔다. 도입 기관의 권한·인력·예산이 없으면 기능 개발만으로 해결된다고 약속하지 않는다.
10. **공익 기록의 공개 범위를 설계한다.** 우회·평가·요구 기록은 동의와 가림을 거쳐 연결한다. 공개 데이터와 규칙은 재사용 가능한 형태를 검토하되 개인정보·권리·신고자 보호를 함께 다룬다. 소상공인 지원 도구는 더 나은 독립 이용 수단부터 안내하며 신고 기능과 구분한다.

### 1. 글자 되살리기: 이미지 속 한국어를 진짜 글자로

**문제·대상:** 통이미지 상품정보를 읽거나 확대하기 어려운 화면낭독·저시력 사용자를 돕는다. 쇼핑앱 9개의 상세 이미지가 모두 같은 이름으로 읽혔고 시각장애인 응답자의 92.2%가 상품정보 확인에 어려움을 겪었다는 2021년 조사가 근거다 [A] ([docs/01-digital-access-environment.md](01-digital-access-environment.md#44-이용자-조사-한국소비자원2021-a)).

**산출물·범위:** 대체 텍스트가 부족한 이미지를 OCR로 읽어 확대·리플로우·화면낭독 가능한 글자로 제공한다. 긴 상세페이지에서 품목별 상품정보·거래조건, 광고·이벤트, 링크·버튼 기능을 구분하고 질문에는 원문 위치를 연결한다. 판결의 상품정보 범위는 [docs/02-private-sector-legal-obligations.md](02-private-sector-legal-obligations.md#61-경과-a)를 참고한다 [A]. PC 확장 뒤 Safari 확장을 검토한다.

**첫 검증·도입 조건:** 식품 상세 50개의 원재료·알레르기·용량 오류율로 품질 하한을 정한다. 쇼핑몰 한 곳에서 텍스트 삽입·식품 항목 정리까지 2~4주를 제안했다. 앱 안 상세페이지에는 확장이 닿지 않으므로 별도 모바일 앱 경로는 미정이다.

**제약·연결:** 공개 상품 페이지만 대상으로 하고 로그인 뒤 주문 내역은 처리하지 않는다. 안전 정보에는 원문·AI 추정 표시를 붙인다. 전사 전체의 공유 캐시 대신 가격·용량 같은 짧은 사실만 공유하는 설계다. 동의받은 누락 통계는 [8번](#idea-8), 엔진은 [12-a](#idea-12-a)와 연결한다.

### 2. 말로 누르기: 한국어 음성 제어

**문제·대상:** 손 떨림·느린 조작 때문에 이용이 어려운 지체·뇌병변장애 사용자에게 한국어 조작 경로를 제공한다. 사례 [C]가 모든 이용자의 음성 제어 필요를 뜻하지는 않는다.

**산출물·범위:** 누를 요소의 번호와 “3번”, “아래로”, “뒤로”, “검색창에 생수 입력” 같은 명령으로 동작한다. PC 한국어 음성 인식 확장부터 Android 접근성 서비스 앱으로 넓히며, 스스로 계획하는 에이전트와 사용자가 요청한 동작을 구분한다.

**첫 검증·도입 조건:** 뇌병변장애 당사자 3명 이상과 명령 10개의 성공률을 확인한다. 번호·명령 10개 확장에 2~3주, 2단계 Android 앱에 2~3개월을 추정했다. 권한·배포 승인과 기기 안 인식의 실제 지원을 확인해야 한다.

**제약·연결:** 조음 특성에 따라 짧은·사용자 지정 명령과 스위치 입력을 검토하고 잘못된 라벨에는 번호·격자를 둔다. 결제·송금은 추가 확인하며 보안 키패드 등 막힌 화면은 조작하지 못한다. 해외 유사 도구의 한국어 지원은 미확인 [B]이므로 경쟁자가 없다고 단정하지 않는다. [5번](#idea-5)·[송금 확인](#small-06-3)은 확장 후보다.
<a id="idea-3"></a>

### 3. 버튼 이름 모음: 증권·은행 앱 라벨 팩

**문제·대상:** 이름 없는 금융 앱 버튼 때문에 막히는 TalkBack 사용자를 돕는다. 증권 앱 사례 [B]와 은행 앱 8곳의 대체 텍스트 미준수 [A]를 참고한다. 근거 범위는 [docs/01-digital-access-environment.md](01-digital-access-environment.md#71-시각저시력)에 있다.

**산출물·범위:** 이름 없는 버튼 후보를 찾고 당사자가 확인한 이름을 앱·버전별 맞춤 라벨 파일로 모아 웹에서 배포한다. 별도 앱보다 파일·기여 운영으로 시작한다.

**첫 검증·도입 조건:** 같은 앱·버전의 두 기기에서 라벨 내보내기·가져오기가 실제로 되는지 하루 실험을 한다. 성공하면 증권 앱 2~3개의 팩에 1~2주를 제안했다. 실패하면 [2번](#idea-2)의 Android 기능으로 옮기는 방안을 검토한다.

**제약·연결:** 소스의 관련 문자열은 확인 [B]했지만 Play 배포판·삼성 기기·iOS 내보내기는 미확인이다. 요소 식별자가 없거나 업데이트로 바뀌면 깨질 수 있어 버전·되돌리기를 남긴다. 버튼 목록은 [6번](#idea-6)의 요구서와 [7번](#idea-7)의 평가 자료다.
<a id="idea-4"></a>

### 4. 쉬운 말 도우미: 받은 문서를 쉬운 말로

**문제·대상:** 문자·고지서·계약서·약관의 할 일을 이해하기 어려운 발달장애인·고령자를 돕는다. ‘복잡하고 어려워서’ 인터넷을 쓰지 않는 지적·자폐성장애인 사례와 수치는 [docs/01-digital-access-environment.md](01-digital-access-environment.md#37-모든-장애유형을-포괄하는-조사-2023-장애인실태조사)에 있다 [B].

2024년 장애인 학대 보도는 피해자의 71.1%가 발달장애인이며 경제적 착취가 18.6%를 차지했다고 전했다 [C]. 명의도용·개통·대출 피해 사례와 함께 쉬운 설명·원문 확인을 검토한 고유 근거다. [당시 보도](https://www.seoul.co.kr/news/society/health-welfare/2025/09/26/20250926500035)

**산출물·범위:** 촬영·공유한 문서의 ‘무엇을·언제까지·얼마’를 쉬운 문장·그림 기호·음성으로 제시한다. 숫자·날짜는 원문 위치와 연결하고 개통·대출 권유·모르는 링크 등 사기 신호를 확인할 단서를 준다. 이미 받은 문서의 이해를 돕는 것으로 발행 원본 관리 [25번](#idea-25)과 구분한다.

**첫 검증·도입 조건:** 요금·관리비·택배·병원 안내 등 10종의 카카오톡 채널에 2~3주를 제안했다. 당사자 검수에 보수를 책정하고 기기 안 처리의 한국어·기기 지원을 확인한다. 미지원 기기의 서버 경로는 가림 후 최소 전송으로 검토한다.

**제약·연결:** 결과는 초안이며 원문을 대조하게 한다. 계약은 서명 전 믿을 만한 사람과 확인하고, 민감한 문서 전체를 기본 전송하지 않는다. 쉬운 내용과 [11번](#idea-11)의 절차 수행은 연결하되 같은 작업으로 취급하지 않는다.
<a id="idea-5"></a>

### 5. 설명 먼저, 행동은 확인 뒤: 브라우징 에이전트

**문제·대상:** 현재 위치·가능한 행동·실행 결과를 파악하기 어려운 시각장애 사용자를 돕는다. 복잡한 결제 화면의 불편은 [docs/01-digital-access-environment.md](01-digital-access-environment.md#44-이용자-조사-한국소비자원2021-a)의 이용자 조사 [A]를 참고한다.

**산출물·범위:** “지금 어디야?”, “뭘 할 수 있어?”, “방금 누른 결과는?”에 답하는 설명 모드가 기본이다. 명시적으로 요청한 때만 한 단계씩 조작하고 결과 상태를 따로 확인한다.

**첫 검증·도입 조건:** 독립 제품보다 [1번](#idea-1)·[2번](#idea-2)의 2단계 기능으로 제안했다. 기간·표본은 미정이다. 사용자 기기·세션에서 허용 목록과 사이트의 자동화 조건을 확인하고 되돌릴 수 없는 행동은 확인받는다.

**제약·연결:** 로그인·결제·본인인증·보안문자를 대신하지 않고 비밀번호·인증서를 보관하지 않는다. 프롬프트 인젝션 [C], 자동화·외부 에이전트 제한 [B·C]과 행동 실패를 고려한다. 모델의 완료 선언만으로 성공을 판정하지 않는다.
<a id="idea-10"></a>

### 10. 우회로 위키

**문제·대상:** 앱 대신 모바일 웹, 다른 인증·상담 수단 등 가능한 경로를 찾아야 하는 이용자를 돕는다. 대체 인증수단 도입 사례 [B]가 있어도 알려지고 유지돼야 쓸 수 있다는 가설이다.

**산출물·범위:** 예매·영상 인증·문자·수어 상담 등 과업별 우회 경로를 정적 웹으로 모으고 마지막 확인일과 확인자의 이용 방식을 기록한다.

**첫 검증·도입 조건:** 금융·교통·쇼핑 과업 30개에 1~2주를 제안했다. 핵심은 콘텐츠 확인·갱신이며 같은 도구의 존재를 별도 조사하지 않아 새 시장으로 판단하지 않는다.

**제약·연결:** 오래된 확인일을 표시하고 개편·버전 변경 때 재확인한다. [7번](#idea-7)과 DB를 공유할 수 있으나 특정 환경의 평가와 시도할 대체 경로를 구분한다. [14번](#idea-14)은 기기·제도·호환 연결, [24번](#idea-24)은 연락처를 넘어 실제 업무 처리까지 다룬다.
<a id="idea-11"></a>

### 11. 따라 하기와 같이 하기

**문제·대상:** 인증서 발급·배달·예약 같은 절차를 혼자 마치기 어려운 발달장애인·고령자와 가족·활동지원사를 돕는다. 조작 사례 [C]와 65세 이상 장애인의 원하는 정보 찾기 26.0%라는 조사 [A]를 참고하되 접속 경험과 구분한다.

**산출물·범위:** 화면 위 단계 안내를 따라 수행하고 막히면 선택한 지원자가 화면을 보며 짚어 준다. 대신 처리하기보다 이해·수행을 돕는 방식이다.

**첫 검증·도입 조건:** 흔한 과업 세 개의 안내에 3~4주를 제안했다. 스스로 원할 때 이용한다는 관점을 적용하고 화면 공유·원격 지원의 실제 연동 범위를 정해야 한다.

**제약·연결:** 비밀번호·인증 화면은 가리고 도움 요청 기록은 사용자가 가진다. [4번](#idea-4)과 이해 지원을 공유하지만 저장·복구·접수 확인 [23번](#idea-23)은 운영 서비스의 별도 기능이다.

<a id="idea-13"></a>

### 13. 확대해도 안 깨지게: 검증하고 되돌리는 페이지 수리기

**문제·대상:** 확대 뒤 레이아웃·대비·초점이 깨지는 저시력 이용자용 브라우저 확장이다. 기존 확대 기능 자체를 복제하기보다 확대 상태에서의 사용을 보완한다. 시각장애·보조기기 통계는 수요를 직접 증명하지 않으며, 대비·초점 등 항목의 어려움은 [docs/01-digital-access-environment.md](01-digital-access-environment.md#42-항목별-준수율-누가-어디서-막히는가-b)의 조사 범위에서 참고한다 [B].

**산출물·범위:** 대비·리플로우·초점을 규칙으로 고치는 저시력 프로필부터 만든다. 원문이 제안한 수리 목표는 명도 대비 4.5:1, 200% 이상 확대에서 가로 스크롤을 만드는 고정 폭 해제다. UD 서체·자간·행간, 고정 폭 해제, 초점 테두리와 가림 보완을 검토한다. 제목·랜드마크·입력 레이블 추정은 구조 프로필의 2단계로 미룬다. 적용 전후 위반이 엄격히 줄어들 때만 적용하고 가시성·클릭 가능성도 확인하며, 자동 추정 표시·미리보기·즉시 되돌리기·사이트별 설정을 둔다.

**첫 검증·도입 조건:** 규칙 세 개와 검증기로 한국 상위 100개 사이트의 퇴행 여부를 본다. 원문은 퇴행 0건 확인 뒤 공개와 2~3주를 제안했으며 실제 달성 결과가 아니다. 기기 안 처리로 시작하고 무거운 페이지·동적 변경을 함께 시험한다. 폰은 원문 기준 Safari 확장 경로를 검토한다.

**제약·연결:** 잘못 추정한 구조가 오히려 탐색을 방해할 수 있어 규칙별 해제가 필요하다. 색 보정의 권리 위험이 낮다는 평가는 조사자의 해석이다. 이미지 속 글자는 [1번](#idea-1), 검사 규칙은 [12-b](#idea-12-b), 동의받은 수리 통계는 [19번](#idea-19)과 연결한다. [확대 중 알림](#small-07-4)은 별도 제품보다 이 도구의 기능 후보다.

<a id="idea-14"></a>

### 14. 보조기기 길잡이: 찾기, 신청하기, 연결하기

**문제·대상:** ‘은행 앱 글씨가 안 보인다’, ‘통화 소리가 안 들린다’는 디지털 과업에서 출발해 저시력자·고령 청각장애인이 보조기기를 찾고 연결하도록 돕는다. 보조기기 미구입 이유 중 적합한 기기·구입처를 모른다는 응답은 안내 수요의 근거지만 경제적 부담까지 안내만으로 해결된다는 뜻은 아니다 [B] ([docs/01-digital-access-environment.md](01-digital-access-environment.md#52-보조기기-필요소지사용2023-장애인실태조사-b)).

**산출물·범위:** 모바일 웹·카카오톡 채널에서 폰의 무료 내장 기능 → 관련 보급 품목 → 당사자 후기 순으로 안내한다. 정보통신보조기기 보급, 교부사업, 건강보험 급여, 보조공학기기, 바우처의 조건·일정과 보청기·폰, 점자단말기·폰, 스크린리더·브라우저의 호환·연결 절차를 다룬다. 품목 중심의 기존 DB와 달리 과업에서 신청·연결까지 잇는 가설이다.

**첫 검증·도입 조건:** 시각·청각 두 유형, 과업 20개, 품목 매핑·호환 표·2027년 신청 일정 알림을 2주 규모로 제안했다. 주된 비용은 콘텐츠 확인·갱신 운영이다. 신청 가능성과 호환성을 담당 기관·제조사 정보로 확인해야 한다.

**제약·연결:** 의료기기 추천·청력 상담을 대신하지 않고 제도·호환·연결 정보만 제공한다. 입력은 저장하지 않고 알림 정보만 최소 수집하며, 광고 없이 당사자 후기를 운영한다는 설계안이다. 확인일과 오래된 항목 표시가 필요하다. [10번](#idea-10)의 지식 DB, [11번](#idea-11)의 단계 안내를 공유하고 보급 실적 공백은 [22번](#idea-22)으로 확인한다.

<a id="idea-23"></a>

### 23. 중간부터 다시: 신청·예약 이어하기

**문제·대상:** 쉬었다 돌아오거나 오류를 수정할 때 입력과 진행 상태를 잃는 이용자를 위해 운영 서비스에 저장·복구를 붙인다. 기존 조작 시간·복잡성 사례가 세션 손실의 발생률까지 입증하는 것은 아니다. W3C 작업 저장 보충 지침을 참고하되, 세션 간 저장을 WCAG 중복 입력 기준의 필수 요구로 바꾸어 설명하지 않는다 [B].

**산출물·범위:** 저장 범위·기간·재개 방법과 저장하지 않는 선택을 제공하고, 단계마다 실제 저장 상태를 알린다. 재접속 때 정상 인증 뒤 완료·남은 일·바뀐 조건과 초점을 복원한다. 재고·가격·자격은 다시 확인하며, 제출 결과가 불명확하면 접수 상태부터 조회해 중복 신청을 막는다. 단순 시간 알림이나 [11번](#idea-11)의 안내와 다른 점은 서비스가 초안을 보존한다는 것이다.

**첫 검증·도입 조건:** 복지관 신청·일반 예약 등 과업 하나에 가상정보로 저장·재접속·오류 복귀·접수 확인 모형을 만든다. 자리 비움, 연결 끊김, 제출 결과 수신 전 중단을 시험하고 재입력·잘못된 복원·중복 접수·결과 이해를 기록한다. 모형 1~2주와 운영 연동은 별도이며 기관이 통합·유지 비용을 부담하고 이용자는 추가 비용 없이 쓴다는 가설이다. [첫 실험](#first-experiment)에서 [28번](#idea-28)과 함께 검증한다.

**제약·연결:** 비밀번호·인증번호·결제 승인은 복원하지 않는다. 초안 권한·공용 기기 노출·삭제·만료를 다루며 저장이 예약·가격 보장을 뜻하지 않게 한다. 기관이 초안·접수 조회를 지원하지 않으면 범용 확장으로 해결한다고 약속하지 않고 단일 기관 구현·설계 패턴으로 좁힌다.

<a id="idea-24"></a>

### 24. 문자로 끝내기: 같은 조건의 상담 인계

**문제·대상:** 막힌 일을 전화로 돌려보내거나 처음부터 설명하게 하는 대신 고객센터·업무 담당자가 문자로 이어받아 처리하는 운영 도구다. 문자부터 검증하되 이용자가 원하는 음성·수어·쉬운 설명도 고려한다. 사람의 도움을 찾는 부담을 줄이라는 W3C 보충 지침을 참고한다 [B].

**산출물·범위:** 이용자가 고른 실패 단계·요청·필요 정보만 전달하고 담당자 변경 뒤에도 상태를 이어받는다. 상담 종료, 업무 완료, 이용자 결과 확인을 따로 둔다. 온라인의 가격·혜택·기회를 대체 경로에서 유지할 권한과 조건을 먼저 합의하고 불가능한 차이는 명시한다. 연락처 모음이면 [10번](#idea-10), 개선 요구 사건이면 [6번](#idea-6)의 범위다.

**첫 검증·도입 조건:** 기관 한 곳의 예약 변경 업무와 기존 문자 상담·수동 인계표로 시작한다. 가상 문의 10건에서 담당자 도달, 설명 반복, 대기, 전화 전환, 변경 성공을 확인한 뒤 당사자 시험을 한다. 기관이 상담 운영비·인계 도구 비용을 부담한다는 가설이며 응대 시간·인력도 포함한다. 반복 문의 감소가 실제 도입 이유가 되는지는 검증한다.

**제약·연결:** 문자만으로 모든 농인이 이용할 수 있다고 보지 않는다. 도움은 선택하게 하고 본 서비스 개선도 계속한다. 기관이 승인한 접근 가능한 인증을 사용한다. 상담원에게 처리 권한이 없어 매번 전화로 돌아가면 화면·챗봇 개발보다 업무 규칙 변경이 먼저다. [26번](#idea-26)은 상담 선호 기능으로 시작할 수 있다.

<a id="idea-25"></a>

### 25. 한 번 쓰고 함께 발행: 접근 가능한 원본 편집실

**문제·대상:** 콘텐츠 제작자가 일반 안내·이미지 홍보물·쉬운 안내의 사실과 정정 시점을 함께 관리하는 도구다. 쉬운 안내가 정정에서 빠지는 빈도는 아직 조사하지 않았다. 이미 발행된 자료를 읽거나 변환하는 [1번](#idea-1)·[4번](#idea-4)·[12-a](#idea-12-a)와 제작 단계의 원본 관리가 다르다.

**산출물·범위:** 대상·할 일·비용·기한·장소·예외·문의의 공통 원본과 사진·도식 설명을 만들고, 형식별 초안·검수·발행 상태를 분리한다. 원문 변경 때 영향받는 산출물과 쉬운 설명의 재검수를 표시한다. 이전 버전·정정 내역과 통제 밖으로 출력·복사된 홍보물의 교체 대상도 남긴다.

**첫 검증·도입 조건:** 기관의 안내문 5개를 일반 웹·쉬운 안내 두 형식으로 관리하고 날짜·비용·자격 변경을 넣어 누락을 찾는다. 숫자 일치와 의미 검수를 구분하며 이용자가 신청 방법·기한·예외를 찾는지 관찰한다. 소규모 흐름의 2~3주 실험을 제안했고 이미지 생성은 뒤로 미룰 수 있다. 발행 기관이 편집·당사자 검수 시간을 부담한다는 가설이다.

**제약·연결:** 같은 숫자를 써도 예외가 빠지면 같은 뜻이 아니다. 자동 결과는 초안이며 긴 이미지에 대체 텍스트만 붙이는 데 그치지 않는다. 담당자가 원본을 유지할 수 없거나 게시 채널이 텍스트·링크를 허용하지 않으면 전 채널 자동 동기화를 약속하지 않는다. 변환 초안만 남으면 독립 제품보다 [4번](#idea-4)·[12-a](#idea-12-a)의 기능이다.

<a id="idea-26"></a>

### 26. 내 이용 방식 카드: 원하는 지원을 골라 전달

**문제·대상:** 이용자가 서비스마다 ‘문자로 연락’, ‘한 단계씩 보기’, ‘시간 조정’을 반복 설명하는 부담을 줄인다는 가설이다. 반복 설명의 빈도·부담은 미확인이므로 다른 다섯 운영 후보보다 탐색을 우선한다. W3C의 개인화 지침은 참고 근거이며 기관 간 카드 규격의 효과를 검증한 자료는 아니다 [B].

**산출물·범위:** 진단명·장애등급 대신 원하는 동작을 사용자가 골라 기관에 보내고, 기관이 적용·미지원·담당자 확인 필요 상태를 회신한다. 항목·기간·공유 대상을 선택하고 해제할 수 있게 한다. 기관 간 자동 공유나 보조기술 사용 탐지는 하지 않으며 카드 없이도 기본 서비스를 이용해야 한다.

**첫 검증·도입 조건:** 앱보다 한 기관의 신청·상담 두 업무에 종이·접근 가능한 양식으로 요청 약 5개를 전달한다. 당사자 5명과 반복 설명·오적용·불필요한 공개·직접 설정 선호를 비교한다. 기관이 설정·상담 연동을 부담하며 여러 기관의 공통 규격은 이후 과제다.

**제약·연결:** 지원 요청이 새 등록·증명 절차가 되거나 장애 관련 사정을 불필요하게 드러내지 않게 한다. 두 업무에서도 적용 가능한 요청이 적거나 설명 부담이 줄지 않으면 독립 제품을 접고 [24번](#idea-24)의 선호 기능으로 합친다. 설정 안내만 하면 [14번](#idea-14)의 범위다.

## 5. 공급자 구현 도구

<a id="idea-12"></a>

### 12. 고치는 쪽을 위한 도구 세 가지

사용자와 산출물이 달라 하위 세 도구를 각각 보존한다. 원문에 없는 개발 기간·시험 표본은 미정으로 둔다.

<a id="idea-12-a"></a>

#### 12-a. 판매자용 대체 텍스트 초안기

**문제·대상:** 상품 등록 판매자의 작성 부담을 줄인다. 입점 판매자 정보에 대한 플랫폼 책임과 하루 약 60만 건 등록 항변의 판단은 [docs/02-private-sector-legal-obligations.md](02-private-sector-legal-obligations.md#62-법원이-확정한-것-a)의 판결 근거다 [A].

**산출물·범위:** [1번](#idea-1)의 추출 엔진을 상품 등록에 붙여 판매자가 확인·발행하는 초안을 만든다. 이용 중 우회와 공급자의 원본 개선을 구분한다.

**첫 검증·도입 조건:** 판매자의 검수·편집·발행 절차를 확인하고 소상공인 무료 제공을 검토한다. 기업용 AI 대체콘텐츠·전문가 검수 서비스가 이미 있어 [C] 생성 기능 자체를 차별점으로 삼지 않는다.

**제약·연결:** 무검수 발행·준수 보장은 하지 않는 설계다. 추출 품질과 판매자 흐름을 각각 검증한다. 여러 형식의 정정·발행 관리로 확장하면 [25번](#idea-25)의 범위다.

<a id="idea-12-b"></a>

#### 12-b. KWCAG 2.2 오픈 검사기

**문제·대상:** 국내 기준의 검사 규칙을 유지·재사용할 개발자·측정 도구 제작자를 돕는다. OpenWAX의 개인 배포와 당시 갱신 공백이 근거다 [B].

**산출물·범위:** KWCAG 2.2의 33개·KS X 3253:2025의 41개 항목을 대조할 공개 규칙을 구상한다 [A] ([docs/02-private-sector-legal-obligations.md](02-private-sector-legal-obligations.md#91-기술-기준의-현행-버전-a)). 기준 항목 전체와 자동 검사 가능 범위를 구분하며 웹·네이티브 앱의 구현을 동일 엔진으로 가정하지 않는다.

**첫 검증·도입 조건:** 우선 규칙·표본·기간은 미정이며 자동화 가능 범위를 검증해 정한다. [기준 대조표](#small-07-1)로 항목 ID·기준 버전을 공유할 수 있다.

**제약·연결:** [6번](#idea-6)·[8번](#idea-8)·[13번](#idea-13)·[19번](#idea-19)이 재사용하더라도 각 도구의 당사자 확인·수동 검증을 유지한다. 자동 검사만으로 준수를 보장하지 않는다.

<a id="idea-12-c"></a>

#### 12-c. 접근성 QR·NFC 주문 웹

**문제·대상:** 매장 운영자가 고객의 다른 주문 경로를 제공하도록 돕는다. 원문에서 확인한 2025년 11월 대체 수단 규정 [A]을 근거로 한 제안이며, 적용 판단은 [docs/02-private-sector-legal-obligations.md](02-private-sector-legal-obligations.md#51-무엇이-바뀌었나-a)의 범위를 따른다.

**산출물·범위:** 접근 가능한 주문 웹을 오픈소스로 제공하고 QR·NFC·매장명 검색에서 진입하게 한다. 별도 주문 웹이며 기존 단말 세션을 이어 조작하는 [16번](#idea-16)과 다르다.

**첫 검증·도입 조건:** QR을 찾기 어려운 사람도 진입·주문할 수 있어야 한다. 첫 매장·표본·기간은 미정이다. QR 주문의 배제 비판 [C]을 검토하고 연결 자체를 접근성으로 취급하지 않는다.

**제약·연결:** 테이블오더 인증 선례 [C]가 새 웹의 사용성·법적 적합성을 보장하지 않는다. 폰 없는 이용자와 현장 대안도 고려하고 [9번](#idea-9)의 작동 기록과 연결한다.

<a id="idea-15"></a>

### 15. 인증 관문 키트: 본인인증과 보안 키패드

**문제·대상:** 인증·보안 입력에서 막히는 이용자와 이를 고칠 인증·금융 공급자를 연결한다. 키패드·얼굴 인식·보안문자 장벽과 대체 수단 권고는 [docs/01-digital-access-environment.md](01-digital-access-environment.md), [docs/02-private-sector-legal-obligations.md](02-private-sector-legal-obligations.md#82-민간-대상-주요-결정20192026-b)의 확인 범위를 따른다 [A~C]. 공급자가 소수라는 보도만으로 현행 시장 전체 수·점유율을 확정하지 않는다.

**산출물·범위:** 세 부분이다. 본인인증 수단을 이용 방식별로 끝낼 수 있는지 기록하는 당사자 평가, 시간 연장·대체 경로·출력·조작 조건의 체크리스트와 시험 시나리오, 접근성과 보안을 검토한 키패드·얼굴 인증 흐름의 공개 구현이다. 평가 부분은 [7번](#idea-7)의 과업 축에 인증을 넣어 재사용한다.

**첫 검증·도입 조건:** 당사자 10명, 인증 수단 6개, 이용 방식 4가지의 공개 보고서를 3~4주 운영으로 제안했다. 레퍼런스 구현은 2단계이며 보안 전문가·공급자 검토가 필요하다. WCAG 2.2의 접근 가능한 인증 원칙과 국내 표준 항목을 대조하되, KS X 3253:2025 원문에 해당 항목이 들어 있는지는 원문 조사에서 확인하지 못했다.

**제약·연결:** 본인 계정·정상 절차로 평가하고 우회·취약점은 공개하지 않는다. 키 입력을 소리로 내는 위험에는 이어폰·진동 등을 검토한다. 다른 생체정보를 더 수집하는 대안보다 시간 조정·사람 확인을 우선한다. 결과는 [6번](#idea-6)의 증거, [18번](#idea-18)의 버전 관측, [12번](#idea-12)의 공급자 개선과 연결한다.

### 16. 키오스크를 내 폰으로: 폰 연동 공개 규격과 레퍼런스

**문제·대상:** 이용자가 익숙한 폰의 보조기술로 키오스크를 조작하고 제조사가 공통 연동을 구현하도록 돕는 제안이다. 폰·웹을 보조 수단으로 다룬 제도 자료 [A·B]와 SiteKiosk 상용 선례 [C]를 참고했지만 공개 규격·국내 적용성을 확인한 결과는 아니다.

**산출물·범위:** QR·NFC로 세션을 연결하고 키오스크와 폰의 상태를 맞추는 공개 규격, 웹 기반 단말 모듈과 폰 웹앱이다. 페어링·시간 연장·종료·정보 최소화를 정한다. [12-c](#idea-12-c)가 별도 주문 페이지라면 이 제안은 주차·민원·도서 등 기존 단말의 과업을 잇는다. 사용자가 익힌 보조기술을 쓴다는 기대가 학습 비용 0을 입증하는 것은 아니다.

**첫 검증·도입 조건:** 규격 초안·웹 데모·당사자 5명 시험을 3~4주로 제안했다. 다음 단계는 제조사 한 곳의 시범 적용이다. 제조사의 채택 유인, 검증·우선구매 평가와의 연결은 정책 제안으로 검토하며 이미 승인된 표준처럼 쓰지 않는다.

**제약·연결:** 가짜 QR에 대비해 NFC·단말 확인 코드·등록 도메인을 검토한다. 결제는 단말·결제사 앱에서 끝내고 연동 세션에 카드 정보를 싣지 않는다. 폰이 없는 사람을 배제하거나 기기 자체 개선을 대체해서는 안 된다. [9번](#idea-9)의 현장 정보, [17번](#idea-17)의 사업자 선택지와 연결한다.

### 7. 당사자 앱 평가: 한국판 AppleVis

**산출물·범위:** 설치·로그인·검색·결제·본인인증 과업과 화면낭독·확대·음성·쉬운 말 등 이용 방식을 교차해 버전별 완료 여부·실패를 기록하고 퇴행을 알린다. 개발자의 자가 신고와 당사자 결과를 나란히 둔다.

### 8. 판결 이행·인증 감시

**문제·대상:** 단체·연구자·정책 담당자가 쇼핑몰 판결과 인증 사이트의 실제 상태를 계속 확인하도록 돕는다. 원문 조사 시점에 3사 이행 보도를 찾지 못했고 인증 사후점검 12,503건 중 취소 0건이라는 자료가 있었다 [A·B] ([docs/02-private-sector-legal-obligations.md](02-private-sector-legal-obligations.md#61-경과-a), [docs/02-private-sector-legal-obligations.md](02-private-sector-legal-obligations.md#92-접근성-품질인증-ab)). 이 수치가 모든 인증의 무의미함을 뜻하지는 않는다.

**산출물·범위:** G마켓·SSG닷컴·롯데온 상세 표본을 **매주** 수집해 대체 텍스트의 유무·품질을 기록한다. 파일명·‘상세이미지’ 같은 값을 구분하고 인증 목록과 현재 검사, 목록 밖 인증마크 표시를 대조한다. 공공데이터 3,676건·NIA 현황은 당시 자료 후보로 제시됐다. 일회성 보고서만을 뜻하지 않는다.

**첫 검증·도입 조건:** 3사 상품 300개를 한 번 측정하고 수동 검증한 보고서를 1~2주로 제안했다. 이미지 탐지와 [1번](#idea-1)·[6번](#idea-6)의 필요를 함께 확인한다. 당시 간접강제 논의·2026년 10월 국정감사 자료 활용도 제안했지만 실제 제출·집행의 결정은 아니다.

**제약·연결:** 약관·부하·공개 방법론을 확인하고 자동 판정을 수동 검증 없이 공개하지 않는다. [19번](#idea-19)은 같은 기반을 공공·민간 전반으로 넓히는 범위 차이다. [docs/05-policy-effect-case-proposals.md](05-policy-effect-case-proposals.md#53-제안-3-사전-등록형-쇼핑몰-판결--도매소매업의-대체-텍스트-준수율)의 관측 빈도를 보완할 수 있지만 정책 효과를 바로 증명하지 않는다.

### 9. 키오스크 작동 지도: ‘있다더니 안 되던데’

**문제·대상:** 기기의 위치만으로 이용 가능 여부를 알기 어려운 시각·휠체어 사용자와 현장 확인자를 돕는다. 종로·동대문 18곳 중 6곳의 미작동 보도는 해당 현장 표본의 근거다 [C] ([docs/01-digital-access-environment.md](01-digital-access-environment.md#63-현장-점검-보도-2026-c)).

**산출물·범위:** 모바일 지도에 작동·미작동·대체 수단, 이어폰·키패드·호출벨 위치·대기·직원 대응을 기록하고 음성·사진 제보, 요구서·월별 요약을 지원한다. 기존 위치 안내와 실제 작동 확인의 차이를 유지한다.

**첫 검증·도입 조건:** 한 구·당사자 10명의 파일럿에 2~3주를 제안했다. 원래 입력 후보인 NIA 위치 API 15157403 [B]는 현재 사용자가 **연결·수집을 보류**한 상태다. 도구 가설 자체의 폐기·전체 보류 결정은 아니며 재개 권한을 뜻하지 않는다. 현재 범위는 [docs/work/W-004-main-history-data.md](work/W-004-main-history-data.md)를 따른다.

**제약·연결:** 소상공인을 괴롭히거나 기관 조사로 오인시키지 않게 한다. 원문에서 예외·대체 조치를 다룬 시설은 대체 수단 기록을 중심으로 하고 공개는 법인부터 시작한다는 안이다. [6번](#idea-6)의 엔진과 [docs/05-policy-effect-case-proposals.md](05-policy-effect-case-proposals.md#54-제안-4-사전-등록형-소기업-제조-의무2027122--동네-배리어프리-키오스크)의 수집 구상을 연결하되 등록·검증·작동 대수를 섞지 않는다.

### 18. 앱 접근성 회귀 관측소: 버전마다 잰다

**문제·대상:** 업데이트 뒤 회귀와 공개되지 않는 공식 진단 사이의 공백을 버전별 관측으로 보완한다. 공식 앱 진단·소비자원 권고와 이용자 사례는 [docs/01-digital-access-environment.md](01-digital-access-environment.md#43-모바일-앱-이용은-모바일로-옮겨갔는데-데이터는-멈춰-있다)의 범위를 따른다 [A~C].

**산출물·범위:** Android 실기기에서 정해진 로그인 전 경로의 화면·접근성 트리를 저장하고 이름 없는 요소, 터치 타깃, 대비, 200% 글자 확대의 잘림을 앱·버전·화면 단위로 공개한다. 퇴행은 [7번](#idea-7)의 당사자 평가로 잇는다. 자동 검사 도구는 기반이지 모든 항목·과업의 접근성을 보장하는 점수가 아니다.

**첫 검증·도입 조건:** 은행 8곳의 현재 버전에서 대체 텍스트·대비·글자 확대 등 자동화 가능한 항목을 재점검하는 2~3주 보고서를 제안했다. 이후 월 1회·새 버전 관측으로 넓힌다. 루팅하지 않은 실기기와 OS 표준 자동화를 검토하며 로그인 뒤는 협력사의 시험 계정이나 당사자 평가가 있어야 넓힐 수 있다. 제3자 앱의 Xcode 감사 가능성과 금융 앱 차단 현황은 미확인이다.

**제약·연결:** 자동화 약관과 공개 범위를 확인하고 비정상 서버 요청을 보내지 않는다. 날짜·버전·화면·재현 절차와 반론 기회를 두며 순위를 매기지 않는다. [15번](#idea-15)은 인증 과업, [22번](#idea-22)은 공식 진단 자료, [접근성 공시 스캐너](#small-07-6)는 부속 지표다.

### 19. 웹 접근성 자동 관측: 공공과 민간을 같은 자로

**문제·대상:** 공공·민간 사이트의 자동 탐지 결과를 같은 방법과 주기로 관찰한다. 민간 연례 수동조사와 WebAIM Million의 선례를 참고한다 [A·B]. [8번](#idea-8)도 이미 주기적 측정을 포함하므로 차이는 ‘계속 측정함’이 아니라 판결·인증 대상에서 넓은 기관·기업군으로 확장하는 범위다.

**산출물·범위:** 공공기관·지자체, DART 상장사 홈페이지, 인증 사이트의 홈페이지와 대표 과업 페이지를 분기별로 관찰한다. [12-b](#idea-12-b)의 규칙에 ‘글자가 든 이미지 가운데 의미 있는 대체 텍스트가 없는 비율’, ‘본문 영역에서 텍스트 대비 이미지 면적’, 320px 폭에서의 가로 스크롤, 플러그인·보안 프로그램 요구 여부를 지표 후보로 더한다. OCR은 홈페이지 한 장부터, 동적 사이트는 렌더링 뒤 확인한다.

**첫 검증·도입 조건:** 공공기관 300곳·상장사 300곳의 지표 5개를 한 번 재는 1~2주 보고서를 제안했다. 공식 명부의 홈페이지 필드를 확인하고 없으면 기관 사이트 정보로 보완한다. 당시 제안한 인증 자료 3,676건은 수집 범위·기간을 확인할 목록이지 현행 전체 모집단으로 확정한 것이 아니다.

**제약·연결:** robots.txt·약관·부하와 공개 절차를 확인한다. 자동 결과를 공식 수동 점수와 합치지 않는다. [8번](#idea-8)과 수집 기반, [13번](#idea-13)과 동의받은 수리 통계를 공유하고 [docs/05-policy-effect-case-proposals.md](05-policy-effect-case-proposals.md)의 결과 지표 후보가 될 수 있다.

### 27. 사기 전에 써 보기: 접근성 구매·납품 검수팩

**문제·대상:** 구매·발주 담당자가 키오스크·예약 솔루션·외부 입력 모듈의 설명을 실제 납품 조건에서 확인하게 돕는다. 현장 작동 사례와 GSA의 구매 흐름을 참고한다 [B·C]. 미국 조달 규칙을 한국의 법적 의무로 옮기는 제안은 아니다.

**산출물·범위:** 과업 요구사항, 제품·납품 버전·환경·알려진 제한, 공급자 증빙, 계약 전 시연과 설치 후 검수, 미해결 항목의 담당·기한·재시험을 한 건으로 묶는다. 공급자 주장과 구매자 확인을 분리하고 현장 공간·장치·소음·직원 대응을 본다. 업데이트·갱신 때 다시 볼 과업을 남긴다.

**첫 검증·도입 조건:** 검사 엔진부터 만들지 않고 문서·증빙·과업 시험·미해결 항목표를 준비한다. 실제 구매 예정 기관 한 곳의 제품 하나에서 설명과 시연을 대조한다. 문서 묶음 1주와 조달 기간은 별도다. 기관이 검수·조정 비용을 낸다는 가설이며 시험 결과를 인수·갱신 결정에 반영할 권한이 없으면 승인 절차부터 확인한다.

**제약·연결:** 체크리스트를 인증마크나 모든 이용자에 대한 보장으로 팔지 않는다. 좋은 평가의 대가를 공급자에게 받지 않으며 계약 문구는 기관의 검토 절차로 넘긴다. 검사 결과만 제공한다면 [12-b](#idea-12-b)로 충분하고, 현장 지도 [9번](#idea-9)·인증 관문 [15번](#idea-15)·의무 안내 [17번](#idea-17)와 구매 결정의 역할을 구분한다.

### 28. 고쳐서 다시 해 보기: 유급 당사자 완주 실험실

**문제·대상:** 수정 권한이 있는 제품팀이 실패 하나와 수정 후보를 가져와 당사자와 시험하고 채택·보류를 결정하는 운영 서비스다. Fable 등의 기존 유급 조사 서비스가 있어 새로운 시장이라고 주장하지 않는다 [C]. 한국어 과업·국내 운영 제약·재시험까지 묶은 작은 구매 단위의 수요는 미검증이다.

**산출물·범위:** 과업의 목표 상태, 기존안·수정안 비교, 실패 장면, 수정 결정, 재시험을 한 묶음으로 낸다. 원한 취소와 장벽 때문에 포기한 경우를 구분하고 수행 중 목표 변경은 이유와 함께 기록한다. 순서를 나누고 학습 효과·도움 개입을 남긴다. 결과가 나쁘면 배포 보류도 정상 산출물이다.

**첫 검증·도입 조건:** 기관 1곳·과업 1개·당사자 6~8명으로 시작하고 모집·접근 가능한 시험 준비가 끝난 뒤 2주를 가정한다. 이용 방식별 실패 단계, 복구, 원치 않은 도움, 결과 이해와 실제 수정 결정을 본다. 제품팀이 모집·진행·참여 보수·재시험 비용을 부담한다는 가설이다. 참여자 보수는 성공·결함 발견 여부와 무관하게 지급하고, 서비스 대금도 좋은 결과가 나와야 받는 구조로 만들지 않는다는 제안이다.

**제약·연결:** 소수 고숙련 참여자의 결과를 모든 장애유형·연령에 일반화하지 않는다. 초보·고령·발달장애인의 모집·진행 방식은 별도 검토한다. 권한·시간·예산 없이 홍보용 참여만 원하는 조직이라면 성립하지 않는다. 공개 앱 후기 [7번](#idea-7), 자동 관측 [18번](#idea-18)·[19번](#idea-19)과 달리 수정안 선택을 다루며 다른 제안의 공통 검증 방식으로도 쓸 수 있다.

## 7. 권리·제도·데이터

### 6. 개선 요구서 도우미: 요구하면 기록이 된다

**문제·대상:** 장벽을 겪은 사용자·단체가 증거, 개선 요구, 답변을 이어 관리하도록 돕는다. 사전 개선 요구가 없었다는 법원 판단의 맥락은 [docs/02-private-sector-legal-obligations.md](02-private-sector-legal-obligations.md#63-법원이-인정하지-않은-것-손해배상-a)에 있다 [A].

**산출물·범위:** 캡처·URL·시각·검사 참고 결과를 묶고 당사자가 확인한 사실만으로 요구서 초안을 만든다. 기업 창구 선택·창구 부재·답변·기한을 로컬에서 추적하며 무응답 때 인권위 절차를 안내한다. AI는 문장 정리·증거 목록화만 하고 위반·승소 여부를 판단하지 않는다.

**첫 검증·도입 조건:** 캡처·체크리스트·템플릿·추적 확장에 2~3주를 제안했다. 영구 무료·광고 및 데이터 판매·변호사 소개 수수료 없음이라는 모델과 단체 협력·지속 재원을 함께 검토한다. 필요한 개별 판단은 단체·공익변호사에게 연결한다.

**제약·연결:** 사용자가 고른 사실을 반영하고 제출은 본인이 한다. 무료만으로 반복 서류 작성의 법적 쟁점이 해소되는 것은 아니다. 실명·발생 시점과 1년 기한·소송 여부·피해자 의사 등 접수·각하 조건, 인터넷·전화 1331·우편·방문 경로를 당시 안내 범위 [B]로 다룬다. [1번](#idea-1)·[3번](#idea-3)의 증거를 받고 [9번](#idea-9)에 요구서 엔진을 재사용한다.

<a id="idea-17"></a>

### 17. 우리 가게 키오스크 의무 계산기

**문제·대상:** 의무·예외·지원 제도가 복잡하고 사칭 사기까지 접하는 소상공인을 위한 조건 입력형 모바일 안내다. 안내문은 있지만 계산기는 찾지 못했다는 조사 범위의 제안이다 [C]. 법적 적용 여부의 확정 판단이나 신고 도구가 아니다.

**산출물·범위:** 법인·소상공인 여부, 50㎡ 미만·근린생활시설·테이블오더 여부, 2025-03-27 이전 설치 여부 등 당시 제안한 여섯 조건으로 관련 조문·기한·확인 창구를 안내한다. 검증 기기·음성안내 → 호환 보조기기·폰 연동 → 인력·호출벨 순으로 선택지를 보여 준다. 지원사업·사칭 경고와 호출벨·대체 수단·담당 직원의 매장 안내문을 만든다.

**첫 검증·도입 조건:** 결정 트리·안내문·공개 규칙 파일을 1주 범위로 제안했다. 무료 운영과 조문 인용, ‘해당할 가능성’ 표시, NIA 지원센터·소상공인 통합콜센터 등 최종 확인 경로를 둔다. 실제 배포 전 조건·지원율·연락처의 현행성을 확인해야 하며 이 문서의 기준일 이후 법률 판정을 확정하지 않는다.

**제약·연결:** 법령 개정·헌재 결정에 규칙이 달라질 수 있어 [20번](#idea-20)의 검토 알림과 묶는다. [16번](#idea-16)·[12-c](#idea-12-c)는 구현 선택지, [9번](#idea-9)은 동의받은 현장 안내다. 익명 선택 집계는 정책 분석의 보조 후보일 뿐 의무 이행률이 아니다.

<a id="idea-20"></a>

### 20. 법제·사건 감시 봇: 바뀌면 알고 연표에 반영

**문제·대상:** 조사자·단체·도구 운영자가 법령·고시·입법·사건·공고 변경을 놓치지 않게 돕는다. 구 고시를 현행처럼 인용한 사례가 있어 기억에 의존한 갱신을 보완한다 [A] ([docs/04-sources-and-verification.md](04-sources-and-verification.md#4-바로잡은-보도와-표기)).

**산출물·범위:** 법제처 연혁, 국민참여입법센터, 열린국회정보, 헌재 사건, 인권위 게시물, NIA·복지부·과기정통부 공고를 접근성 주제로 걸러 주간 다이제스트와 연표 추가 행을 제안한다. 입법예고 마감과 심사 단계도 구분한다. 기존 알림 서비스와 달리 여러 출처를 연결하는 가설이며 연표를 검토 없이 확정 갱신한다는 뜻은 아니다.

**첫 검증·도입 조건:** 법제처·입법예고·의안·인권위 네 출처와 다이제스트·행 제안을 1주로 제안했다. 첫 달은 사람이 거른 결과로 키워드의 누락·소음을 조정하고 API·게시판 변경 실패를 알린다.

**제약·연결:** 기존 계류 사건·기한은 당시 조사 시점의 감시 후보다. [17번](#idea-17) 규칙, [21번](#idea-21)의 새 사건, [22번](#idea-22)의 자료 공백과 [docs/03-timeline.md](03-timeline.md)·[docs/05-policy-effect-case-proposals.md](05-policy-effect-case-proposals.md)를 잇는다.

<a id="idea-21"></a>

### 21. 디지털 접근성 결정례·판례·시정명령 아카이브

**문제·대상:** 단체·연구자·요구서 작성자가 디지털 접근성 사건을 매체·쟁점·결과로 찾고 인용하도록 돕는다. 기존 결정례·판례 DB를 대체하기보다 흩어진 공개 기록을 연결한다.

**산출물·범위:** 날짜·기관·공공/민간·업종·매체·쟁점·결과·근거 조문·원문·검증 등급을 구조화한 공개 데이터와 검색 사이트다. 권고·각하·기각·수용·시정명령·판결을 구분한다. [6번](#idea-6)에 쓸 원문 인용을 제공하며 사건 수를 곧 위반 발생률로 해석하지 않는다.

**첫 검증·도입 조건:** [docs/02-private-sector-legal-obligations.md](02-private-sector-legal-obligations.md)·[docs/03-timeline.md](03-timeline.md)의 당시 약 40건을 정적 사이트·CSV로 옮기는 1주를 제안했다. 이후 공개 DB 검색으로 넓힌다. 법적 의무·과도한 부담 판단의 사례를 모으는 것이며 적용 결론을 자동 작성하지 않는다.

**제약·연결:** 비공개 피진정인을 추정하거나 원 공개 범위 이상의 개인정보를 복원하지 않는다. 인용은 원문·출처로 한정한다. [20번](#idea-20)은 새 사건 수집, [22번](#idea-22)은 닫힌 자료 확보로 역할이 다르다.

<a id="idea-22"></a>

### 22. 정보공개청구 레지스트리: 닫힌 데이터를 열고 열린 것을 모으기

**문제·대상:** 접근성 자료가 필요한 조사자·단체가 청구를 반복하지 않고 문안·결정·공개 자료를 축적하게 한다. 공식 자료를 얻는다고 자동 측정과 전문가 점수가 같아지는 것은 아니다.

**산출물·범위:** 청구 기관·범위·부분공개 대안을 담은 템플릿, 신청·결정·사유 조문·이의신청의 레지스트리, 가림·이용조건 확인 뒤 구조화한 자료다. 제출은 각자 한다. 공개 데이터와 분석 참고 레포에 기여한다는 제안이다.

**첫 검증·도입 조건:** 아래 당시 공백 여덟 건의 문안과 공개 스프레드시트, 앱 진단 결과 청구 한 건을 1주 준비로 제안했다. 원문에서 확인한 공개 결정 기간은 10일·연장 시 추가 10일 [B]이며 실제 자료 확보를 보장하는 일정이 아니다. 이미 확보되거나 보류된 자료는 현재 작업 상태를 먼저 확인한다.

| 당시 청구 후보 | 기관·확인할 범위 |
|---|---|
| 2022~2025 앱 진단·2025 AI 서비스 진단 | 과기정통부·NIA: 앱별 점수·업종·결과, 어려우면 익명·업종 집계 |
| 2026년 1월 말~2026-06-30 접수 키오스크 진정 50건 | 인권위: 처리 결과 통계 |
| 2025~2026 차별시정심의위원회 | 법무부: 개최 일자·안건 수 |
| 인증 사후점검 12,503건 | 과기정통부·NIA·인증기관: 연도·결과 유형별 집계 |
| 최근 공공 웹 접근성 조사 | 행안부: 공개 가능한 결과 |
| 정보통신보조기기 보급 실적 | NIA·시도: 연도·품목별 대수 |

| 2024 발달장애인 실태조사 | 복지부: 당시 찾지 못한 결과 |

**제약·연결:** 영업비밀·내부검토 등 비공개 사유와 통계 형태의 대안을 남기고, 개인정보·제3자 정보·재공개 권리를 확인한다. 대리 청구나 같은 청구의 반복을 유도하지 않는다. [7번](#idea-7)·[8번](#idea-8)·[18번](#idea-18)·[19번](#idea-19)의 비교 근거와 [docs/05-policy-effect-case-proposals.md](05-policy-effect-case-proposals.md)의 자료 공백을 잇는다.

## 10. 조건에 따라 시작 순서를 고르기

하나의 전체 순위를 정하지 않는다. 당시 제안한 공익 감시·자료 확보와 협력 기관이 필요한 제품 실험은 목적이 다르며, 현재 저장소의 확정 작업 순서를 대신하지 않는다.

| 목적·확보한 조건 | 첫 후보와 산출물 | 선행 확인 |
|---|---|---|
| 공개 자료로 공익 감시를 시작 | 8의 판결·인증 표적 보고서, 22의 앱 진단 청구, 20의 변경 감시 | 공개·반론 절차, 청구 대기, 현재 자료 확보 상태 |
| 앱 회귀를 관측할 운영 역량 | 18의 은행 앱 재점검과 7의 당사자 평가 | 실기기·허용 화면·참여 보수·유지 인력 |
| 이용자 도구를 검증할 참여자 | 1+13의 읽기·수리, 또는 15+7의 인증 평가 | 어떤 이용 방식·과업에서 기존 도구가 부족한지 |
| 신청·예약 서비스를 바꿀 기관 | 23을 만들고 28로 기존안과 비교 | 초안·접수 상태 접근 권한, 준비 뒤 실험 일정 |
| 업무 권한이 있는 문자 상담팀 | 24, 필요하면 26 일부 | 실제 처리 가능 업무·동등한 조건·응대 인력 |
| 안내문을 반복 제작하는 기관 | 25의 두 형식 정정·재검수 흐름 | 공통 원본을 계속 관리할 동기·게시 채널 |
| 구매·갱신 예정 기관 | 27의 요구사항·시연·인수 시험표 | 시험을 계약 결정에 반영할 권한 |
| 당사자와 수정팀을 연결할 수 있음 | 28의 유급 실험 한 건 | 실제 수정·보류 권한과 재시험 예산 |
| 협력 기관이 아직 없음 | 문제 인터뷰·가상 모형·도입 조건 확인 | 범용 연동·상담 처리·구매 효과를 먼저 약속하지 않기 |

당시 공익 제안은 ‘8을 먼저, 청구 22는 대기 때문에 일찍, 변경 감시 20과 앱 관측 18을 병행’이었다. 2026-09-30의 이용자 제품 선택은 이미지 읽기·기록의 1(+6)과 한국어 음성 제어 2 사이였고, 2026-10-02의 추가 제안은 저시력 1+13과 인증 관문 15+7의 비교였다. 서로 다른 탐색 관점이며 하나의 확정 순위로 대체하지 않는다. 운영 중심의 3+7+10, 대표 통계의 사각을 다루는 4+11 조합도 후보로 남긴다. 제품 실험의 기본 조합은 23+28이지만 재시작 문제가 드물거나 기존 저장으로 충분하면 고집하지 않는다. 26의 독립 제품 우선순위는 지원 가능한 항목과 설명 부담의 변화가 확인되기 전까지 낮게 둔다.

### 11.1 작은 기능 실험으로 먼저 확인할 것

라벨 이동은 [3번](#idea-3)의 두 기기 실험, OCR은 [1번](#idea-1)의 식품 50개, 한국어 명령은 [2번](#idea-2)의 당사자 3명·명령 10개, 판결 대상 표본은 [8번](#idea-8)의 상품 300개, 수리 퇴행은 [13번](#idea-13)의 사이트 100개에서 먼저 확인한다. 모두 하루~일주일의 사전 확인 후보였으며 수행 결과가 아니다.

### 11.2 신청을 중단해도 이어서 끝낼 수 있는가

| 결과 이해 | 저장·접수·완료·취소 중 현재 상태를 이용자가 확인할 수 있는지 |
| 운영 부담 | 기관의 연동·문의 처리·수정·검수 시간 |

과업 안내를 받고 시도를 시작한 건을 분모로 삼고 첫 조작 전 접근 실패도 포함한다. 배정·시작·중단 수를 함께 적으며 안전상 시도하지 못한 과업은 미실시로 분리한다. 다른 사람 정보 노출이나 중복 접수는 중단·수정 사유다. 작은 시험에서 사고가 없었다고 안전성이 입증된 것으로 쓰지 않는다.

### 11.3 정책 분석과 연결하는 범위

주요 질문·지표를 미리 정하고 이미 본 자료와 추가 가설을 구분한다. 한 사람이 여러 과업을 수행한 횟수는 독립 참여자 수가 아니다. 작은 실험의 결론은 해당 조건의 실패·수정 결과이며 전국 정책 효과가 아니다. [docs/05-policy-effect-case-proposals.md](05-policy-effect-case-proposals.md)와 연결하려면 기관별 도입·실사용 시점, 과업·측정 정의, 버전, 동시 변경을 남긴다. 개인정보와 업무 내용을 제외한 설계·실패 유형·집계부터 공개하고 원자료는 별도 동의·재식별 검토가 필요하다.

## 12. 조사 범위와 남은 확인

통합 전 첫 조사 묶음은 웹 검색 약 110회, 두 번째는 검색·원문 접속 각각 약 20회를 사용했다. 세 번째는 기존 조사·작은 아이디어까지 대조하고 작업 저장·사람 도움·개인화·구매·유급 조사 선례를 추가 확인했다. 추가 사실의 최고 등급은 원문 기준 [B]이며, 앞선 조사에서 가져온 [A] 근거는 그 범위를 유지한다. 법률 위험·시장 공백·효과·기간·비용은 확정 사실과 구분한다.

당사자 인터뷰, 국내외 경쟁 제품의 망라 조사, 법령 현행성의 전면 재검증은 하지 않았다. 플랫폼 언어·기기 지원, 배포 심사, 보안 공급자 목록·점유율, 제3자 앱 감사, 기관 명부 필드 등은 카드와 근거 표의 미확인 사항을 따른다. ‘없다’ 대신 ‘이번 조사에서 찾지 못했다’고 표현하고, 보유·이용·등록·검증·작동의 다른 지표로 수요를 산출하지 않는다.

다음 조사에서는 반복 입력·상담 인계의 빈도, 기관의 초안·처리 권한, 원본 유지 동기, 지원 카드의 실제 부담 감소, 구매·수정 결정 권한과 비용 지불 의사를 확인해야 한다. 아이디어 수를 늘리기보다 누구와 어떤 가설을 시험했고 무엇을 유지·축소·중단했는지 남긴다.

### 13.4 해외 선례에서 얻는 설계 가설

사실·표본의 범위는 각 행의 등급을 따르고, ‘교훈’은 제안의 설계 해석이다. 기존 연구의 퇴행 0건·성공률을 새 도구의 성능 보장으로 옮기지 않는다.

| 선례 | 사실 | 교훈 |
|---|---|---|
| 접근성 오버레이 | FTC는 accessiBe가 코드 한 줄로 어떤 사이트든 WCAG를 준수하게 한다고 근거 없이 주장했다며 100만 달러 지급을 명했다(2025.4.22 확정, 20년간 연례 보고) [B]. 오버레이를 비판하는 Overlay Fact Sheet에 1,000명 넘게 서명했다 [C]. UsableNet은 2024년 접근성 소송 4,000건 이상 가운데 위젯을 설치한 기업이 1,000곳 이상이었다고 집계했다 [C]. 지적된 문제는 자동 수정의 신뢰성, 동적 UI 대응 실패, 보조기술 사용 탐지로 인한 장애 노출이다 [C] | '준수 보장'을 약속하지 않는다. 사이트에 심지 않고 사용자가 고르게 한다. 보조기술 사용 사실을 외부에 넘기지 않는다 |

| 당사자 평가 | AppleVis: 회원이 앱별 접근성 등급을 매겨 공개한다 [C]. Apple 접근성 영양 성분표는 자가 신고이고, 문서에 사전 검증 절차가 없다 [B] | 기업의 신고와 당사자 결과를 대조한다. '공통 과업' 단위로 평가한다 |
| AI 에이전트 | 시각장애인 8명이 3주 동안 데스크톱 앱 12개에서 명령 1,258개를 쓴 연구: 가장 나은 모델(GPT-5)의 성공률 52.5%, 실패 유형에 종료 실패 포함(2026.9, 작성 시 초록 재확인) [B]. 에이전트 성공률이 기본 78.3%에서 키보드 전용 41.67%, 확대 환경 28.3%로 떨어진다는 연구(2026.2, 작성 시 초록 재확인) [B].
